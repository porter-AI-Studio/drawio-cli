實戰：AI Agent 模板

解構內建的 ai-agent 系統架構模板，學習如何以 JavaScript 動態控制多層級 XML 的生成。

AI Agent 模板架構設計

內建的 ai-agent 範本是一個 5 層泳道架構的 AI 代理系統，包含 36 個測試點保護其穩定性。其邏輯分層如下：

  • Layer 3 - User Interface（藍色）：前端用戶介面，含 UI1 (War Room) 及 UI2 (AI Agent Q&A)。
  • Layer 2a - Operational Hub（綠色）：核心操作與快取數據庫，包含實體節點 OH1 ~ OH4。
  • Layer 2b - Knowledge Base（紫色）：知識庫儲存與 RAG 向量檢索，包含 KB1 ~ KB5。
  • Layer 1 - Adapters（紅色）：硬體與協定適配器，包含 A1 ~ A3。
  • KB Sources（橘色）：底層原始知識來源，包含 S1 ~ S4。

泳道 (Swimlane) XML 設計

在 Draw.io 中，泳道或容器節點的 style 必須設定為 swimlane;。以 Layer 3 泳道為例： 

<!-- 泳道容器 -->
<mxCell id="L3" value="Layer 3 - User Interface" style="swimlane;startSize=35;fillColor=#dae8fc;strokeColor=#6c8ebf;fontStyle=1;fontSize=13;align=center;" vertex="1" parent="1">
  <mxGeometry x="50" y="30" width="1300" height="155" as="geometry" />
</mxCell>

子元件相對座標定位

由於 Layer 3 泳道的 id 為 L3，所有放置於該泳道內的子節點都必須指定 parent="L3"，且座標 x, y 必須是相對於 L3 左上角 (50, 30) 的偏移： 

<!-- 子元件：War Room (相對座標定位) -->
<mxCell id="UI1" value="War Room&#xa;(Realtime Data Hub UI)" style="rounded=1;whiteSpace=wrap;html=1;fillColor=#fff2cc;strokeColor=#d6b656;fontSize=11;" vertex="1" parent="L3">
  <!-- x=130, y=50 實際在畫布的絕對位置是 (50+130, 30+50) = (180, 80) -->
  <mxGeometry x="130" y="50" width="240" height="70" as="geometry" />
</mxCell>

跨泳道連線 (Edges) 設計

跨泳道連線是用來表達數據流的指向。儘管連線的兩端屬於不同泳道的節點，連線的 parent 仍必須設為頂層 "1"，並透過 source 與 target 明確關聯： 

<!-- 跨容器連線：UI1 (位於 L3) 指向 L2a 泳道 -->
<mxCell id="E1" style="edgeStyle=orthogonalEdgeStyle;rounded=0;" edge="1" source="UI1" target="L2a" parent="1">
  <mxGeometry relative="1" as="geometry" />
</mxCell>

座標佈局規則

五個泳道垂直排列，每個泳道高度為 155px，間距為 10px，起始 x 位置均為 50px。完整佈局公式如下： 

const CANVAS_X = 50;        // 所有泳道左邊距
const LANE_WIDTH = 1300;    // 所有泳道寬度
const LANE_HEIGHT = 155;    // 每層泳道高度
const LANE_GAP = 10;        // 泳道間距
const TITLE_H = 35;         // 泳道標題列高度

// 各泳道 y 座標
const L3_Y  = 30;                            // Layer 3
const L2a_Y = L3_Y  + LANE_HEIGHT + LANE_GAP; // Layer 2a
const L2b_Y = L2a_Y + LANE_HEIGHT + LANE_GAP; // Layer 2b
const L1_Y  = L2b_Y + LANE_HEIGHT + LANE_GAP; // Layer 1
const KBS_Y = L1_Y  + LANE_HEIGHT + LANE_GAP; // KB Sources

36 測試點分佈

測試套件的 36 個測試點涵蓋以下四大類別：

類別測試數量驗證內容
XML 格式驗證 4 項 回傳型態為字串、開頭 <?xml、含 <mxfile、含 <mxGraphModel
泳道存在性 5 項 5 個泳道 ID（L3、L2a、L2b、L1、KBS）全數存在
節點完整性 20 項 UI1/UI2、OH1~OH4、KB1~KB5、A1~A3、S1~S4 及其文字標籤
連線與檔案輸出 7 項 E1~E4 邊存在、邊標籤正確、檔案實際寫入硬碟且不為空

延伸模版：AI Agent 熱力圖著色版

本專案還提供了 ai-agent-heatmap 範本。它的本質結構與 ai-agent 相同，但引入了熱力圖著色機制：

  • 藉由將特定的節點（如 Operational Hub 或 KB）替換為不同明暗度（或漸層）的色彩，用以表示在高負載或高頻存取下的元件負載程度。
  • 這些色彩是透過 JavaScript 動態代入 fillColor 與 strokeColor 參數，展現了「程式碼繪圖」在動態視覺化上的強大潛能。
// 熱力圖著色：依負載程度動態代入色彩
function getHeatColor(loadLevel) {
  // loadLevel: 0.0（冷）~ 1.0（熱）
  if (loadLevel < 0.3) return { fill: '#d5e8d4', stroke: '#82b366' }; // 綠：低負載
  if (loadLevel < 0.6) return { fill: '#fff2cc', stroke: '#d6b656' }; // 黃：中負載
  if (loadLevel < 0.8) return { fill: '#ffe6cc', stroke: '#d79b00' }; // 橘：高負載
  return { fill: '#f8cecc', stroke: '#b85450' };                      // 紅：過載
}
