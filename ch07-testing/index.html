第 7 章 · Part 4：測試與進階應用

單元測試實務

建立持續驗證機制，保障圖表範本不會因語法或邏輯修改而毀損。

測試架構介紹

為了確保自動產出的圖表在任何時候都能被 Draw.io 正確解析，本專案在 test/test.js 中實作了一套輕量級的測試套件。 該套件不依賴 Jest 或 Mocha 等龐大框架，僅透過純 JavaScript 對產出的 XML 檔案與節點結構進行語法級與斷言（Assertion）級的檢驗。

執行測試指令

在專案根目錄下，執行以下命令來執行測試：

npm test

該指令底層實際執行的命令為：

node --experimental-vm-modules test/test.js
⚠️
為什麼需要 --experimental-vm-modules？

因為本專案使用了 ESM（ES Modules）架構，Node.js 原生執行測試檔時，若涉及虛擬機器（VM）或非同步 ESM 動態載入，必須加上該實驗性標記，否則會發生 import 語法載入錯誤。

測試核心範疇

測試套件主要檢驗以下三大維度：

1. XML 格式與標籤正確性

驗證模版輸出的字串是否為合法的 XML：

  • 確認字串開頭是否為 <?xml。
  • 確認是否包含 Draw.io 的核心包裝標籤 <mxfile 與 <mxGraphModel。

2. 泳道（Layers）與節點（Nodes）完整性

自動掃描生成字串，確保所有的核心元素沒有在代碼修改中被遺漏：

// 驗證 5 大分層泳道存在
test('Layer 3 (L3) present', () => assert(xml.includes('id="L3"')));
test('Layer 2a (L2a) present', () => assert(xml.includes('id="L2a"')));

// 驗證特定功能節點存在性與內容
test('UI1 (War Room) present', () => assert(
  xml.includes('id="UI1"') && xml.includes('War Room')
));

3. 連線（Edges）與標籤驗證

驗證關係連線是否正確，並且連線上的註解標籤沒有缺漏：

test('E3 has label "poll / write"', () => assert(xml.includes('poll / write')));
test('E4 has label "ingestion pipeline"', () => assert(xml.includes('ingestion pipeline')));

4. 實體檔案輸出驗證

測試套件會實際呼叫 generate() 函式，將檔案寫入暫存路徑 test/output/test-output.drawio，然後檢查檔案是否存在，並確認寫入的硬碟資料內容是否完整無損。

測試報告範例

測試全數通過時，終端機會列印出綠色打勾標示並顯示：

draw-cli test suite

Template tests:
  ✓ aiAgentTemplate returns a string
  ✓ XML starts with <?xml
  ...
Results: 36 passed, 0 failed
