第 1 章 · Part 1：介紹與安裝

drawio-cli 介紹

透過程式碼（Code-driven）動態生成結構化、美觀的 Draw.io 架構圖與對比表。

專案背景

在軟體工程與系統設計中，架構圖與流程圖是團隊溝通最重要的媒介之一。然而，傳統手動繪製圖表（如使用 Draw.io 網頁版或桌面版）面臨以下缺點：

  • 維護成本高：每當架構稍有變動，必須重新調整大小、對齊、排版，非常耗時。
  • 無法版本控制：`.drawio` 檔案本質是 XML，但網頁版產生的格式通常雜亂無章且帶有壓縮資訊，難以在 Git 進行有意義的 Diff 對比。
  • 無法自動化：當系統架構、監控熱力圖或部署狀態改變時，無法自動同步更新圖表。

為了解決這些痛點，drawio-cli 應運而生。

原版與本地 Node.js 版本的差異

本專案的核心概念是參考開源專案 rlespinasse/drawio-cli。然而，原版專案存在以下限制：

  • 已停止維護（Deprecated）：官方已宣布棄用，轉向基於 Headless Desktop 的方案。
  • 環境沉重（Docker-based）：使用時必須拉取 Docker 映像檔並執行，對本地輕量化開發不友善。

本專案使用 ESM Node.js 重新實作，完全擺脫 Docker 依賴，以最輕量、最快速的方式，在終端機直接透過 JavaScript 代碼產出結構化的 .drawio XML 檔案。

ℹ️
核心設計理念：代碼即圖表（Diagram as Code）

不使用複雜的圖形處理庫，而是直接解析 Draw.io 的底層 XML 結構，透過 JavaScript 模版引擎以「純文字宣告」的方式動態計算幾何座標、色彩與元件，以最直覺的方式產出圖表。

核心功能特性

本專案具備以下核心亮點：

特性 說明
無 Docker 依賴 基於純 Node.js ESM 撰寫，執行快速，一秒產出。
多套精美範本 內建 7 種美觀範本，涵蓋 AI Agent 泳道架構圖、9x9 儀表板、漸層色票、手繪風流程圖等。
高質感配色 使用精心調配的 HSL 與 Tableau 配色方案，告別傳統高飽和度刺眼配色。
嚴格 XML 驗證 符合 Draw.io 核心架構規範，防止 XML 語法或轉義錯誤導致檔案毀損。
全域指令支援 支援 npm link，在終端機內隨時隨地呼叫 draw-cli 指令。

本專案適合誰？

  • 想將系統架構圖併入 Git 版控，讓架構與代碼同步演進的工程師。
  • 需要在 CI/CD 流程中，根據部署狀態自動動態產生監控熱力圖或部署流程圖的 Devops 團隊。
  • 不希望浪費時間在 Draw.io 手動對齊元件、微調像素，而是喜歡用代碼精確定義位置的開發者。
⚠️
警語

由於生成的 .drawio 檔案是純 XML，在編輯或手動新增元件到代碼模版時，必須遵循嚴格的 XML 轉義規則（例如 & 與換行符），否則 Draw.io 會解析失敗。這些細節將在第 5 章中詳細說明。
