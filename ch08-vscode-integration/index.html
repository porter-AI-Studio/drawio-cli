VS Code 整合應用

建立高效的本地圖表編輯工作流，實現「代碼生成、編輯器預覽、筆記整合」三合一。

VS Code 整合：即時預覽與編輯

雖然 drawio-cli 能快速產生 .drawio 檔案，但若每次都要開啟瀏覽器或桌面版 Draw.io 才能確認外觀，會降低開發效率。 為此，我們強烈建議整合 VS Code 整合插件。

安裝整合插件

在 VS Code 的擴充套件商店中搜尋並安裝由 Henning Dieterichs 開發的穩定版插件：
Draw.io Integration (ID: hediet.vscode-drawio)。

或者，您可以在終端機中執行快速安裝指令：

code --install-extension hediet.vscode-drawio

使用方式

  • 當您在 VS Code 中點擊 drawio-cli 產生的 .drawio 檔案時，插件會自動以**視覺化繪圖介面**直接打開它。
  • 您可以在該介面中直接拖曳、新增元件或修改屬性。存檔後，底層的 XML 程式碼會自動同步更新。
  • 如果您想直接查看底層的 XML 代碼，只需對檔案按右鍵，選擇「開啟方式...（Open With...）」，並選擇「文字編輯器（Text Editor）」即可。
💡
開發工作流建議

您可以將 VS Code 視窗切割為兩欄，左欄開啟範本的 JavaScript 程式碼，右欄開啟產出的 .drawio 圖表。每次執行 draw-cli generate 後，右欄的圖表會自動即時重新整理，帶給您無縫的即時預覽體驗！

Obsidian 整合：知識庫圖表管理

如果您使用 Obsidian 來管理您的技術筆記與專案文件，您也可以將產出的圖表直接置於筆記中。

預設情況下，Obsidian 為了安全與簡潔，不會顯示 .drawio 等自訂副檔名的檔案。請依照以下步驟啟用支援：

  1. 開啟 Obsidian，點擊左下角的 設定（Settings）。
  2. 選擇 檔案與連結（Files and links）。
  3. 將 偵測所有檔案副檔名（Detect all file extensions） 選項切換為 開啟（ON）。

啟用此設定後，您就可以在 Obsidian 筆記中以雙鏈格式（例如 [[System_Architecture.drawio]]）直接參照、開啟或管理您的系統架構圖了。

draw.io 官方 MCP Server 整合

2025 年，draw.io 官方（JGraph）發佈了 @drawio/mcp MCP Server， 讓 AI 編程助手（如 Claude Code）能透過自然語言描述，直接在瀏覽器開啟 draw.io 編輯器並生成圖表。

與 drawio-cli 的定位比較

面向 drawio-cli（本工具） @drawio/mcp（官方 MCP）
輸出格式 本地 .drawio 檔案（可版控） 在瀏覽器中開啟 draw.io 編輯器
自動化 完全自動化，適合 CI/CD 流水線 需要瀏覽器互動，適合即時設計
版本控制 生成的 XML 可直接 Git Diff 需手動儲存後才能版控
依賴 純 Node.js，無外部依賴 需要 Node.js + npx + 瀏覽器
範本管理 精心設計的內建範本 + 自訂擴充 支援 XML / CSV / Mermaid 輸入
💡
混合使用策略

最佳實踐是「兩者互補」：用 drawio-cli 維護版控中的架構圖主版本，用 @drawio/mcp 在需要即時設計修改時快速探索想法，確認後再更新到範本程式碼中。

匯出 PNG／PDF：搭配 draw.io 桌面版 CLI

drawio-cli 負責產生 .drawio 原始檔，若需要進一步匯出為 PNG 或 PDF，可搭配 draw.io 桌面版應用程式的命令列功能： 

# Windows：安裝 draw.io 桌面版後
# 通常位於 C:Program Filesdraw.iodraw.io.exe

# 匯出為 PNG（-x 指定輸出格式，-o 指定輸出路徑）
"C:Program Filesdraw.iodraw.io.exe" -x -f png -o output.png input.drawio

# 匯出為 PDF
"C:Program Filesdraw.iodraw.io.exe" -x -f pdf -o output.pdf input.drawio

CI/CD 自動化：圖表隨 Code 同步更新

將 drawio-cli 整合到 CI/CD 流水線，可以實現「每次程式碼部署時自動更新架構圖」的效果。

GitHub Actions 範例

# .github/workflows/update-diagrams.yml
name: Update Architecture Diagrams

on:
  push:
    branches: [main]
    paths:
      - 'src/**'              # 當 src/ 有變動時觸發

jobs:
  generate-diagrams:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install drawio-cli
        run: |
          cd /path/to/Draw_io_cli
          npm install
          npm link

      - name: Generate diagrams
        run: |
          draw-cli generate ai-agent docs/diagrams/system-architecture.drawio
          draw-cli generate ai-agent-heatmap docs/diagrams/system-heatmap.drawio

      - name: Commit updated diagrams
        run: |
          git config --local user.name "GitHub Actions"
          git add docs/diagrams/
          git diff --staged --quiet || git commit -m "docs: auto-update architecture diagrams"
ℹ️
為什麼這比手動維護更好？

傳統上架構圖跟不上代碼演進，往往在文件中看到的圖已是過時的。透過 CI/CD 自動更新，架構圖與代碼永遠保持同步，且每次更新都有 Git 提交記錄可追蹤。
