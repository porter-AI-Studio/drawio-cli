第 3 章 · Part 2：核心功能與架構

CLI 目錄與結構

了解 drawio-cli 內部模組的劃分與合作機制，打下自訂開發的基礎。

專案目錄概覽

drawio-cli 採用簡潔、直覺的 Node.js ESM 專案目錄設計，結構如下：

C:\VSCode_Proj\Draw_io_cli\
├── package.json         # 專案組態與依賴描述 (ESM 指定)
├── bin/
│   └── draw-cli.js      # CLI 入口，負責接收並解析終端機指令
├── src/
│   ├── generator.js     # 核心產生器，控制模版載入與檔案寫入
│   └── templates/       # 存放所有圖表 XML 範本的目錄
│       ├── ai-agent.js
│       ├── ai-agent-heatmap.js
│       ├── nine-nine-grid.js
│       └── ...
└── test/
    └── test.js          # 單元測試與整合驗證套件

核心組件角色分析

1. 指令入口：bin/draw-cli.js

這是 CLI 的命令解析層。最頂部標註了 #!/usr/bin/env node 以支援 Unix/Linux 系統下的執行檔封裝。 本模組使用熱門的 commander 程式庫，用來定義終端機的指令（如 generate 與 list）、描述、參數規格以及錯誤處理。 它接收使用者參數後，會將對應的模版名稱與輸出路徑傳遞給後端的 generator.js 執行。

2. 生成中樞：src/generator.js

本模組是程式邏輯的路由器。它負責：

  • 匯入 src/templates/ 中註冊的所有範本函式。
  • 維護一個 templates 對照表（Mapping Object），將指令參數與實際模版進行配對。
  • 在執行 generate 時，呼叫對應的範本函式生成 XML 字串。
  • 檢查並遞迴建立目標輸出資料夾（使用 mkdirSync(..., { recursive: true })），再將 XML 字串寫入實體檔案中。

3. 範本倉庫：src/templates/

每個 JavaScript 檔案代表一個圖表範本，並導出一個標準的生成函式。例如 ai-agent.js 導出 aiAgentTemplate()，此函式不帶參數並回傳純 XML 字串。 這種設計將業務邏輯（圖表形狀、位置、配色、連線）與控制邏輯（CLI 語法、檔案寫入）完全解耦，開發者可以非常容易地擴充新範本，而不用修改 CLI 本身。

4. 驗證套件：test/test.js

針對產出的 XML 進行單元級與整合級測試。它不依賴外部龐大的測試框架，以純 JavaScript 快速驗證生成檔案的正確性與節點存在性。

ℹ️
ESM (ECMAScript Modules) 的設計優勢

本專案在 package.json 中設定了 "type": "module"。使用 ESM 讓我們能夠直接使用現代 JavaScript 的 import/export 語法，使代碼結構更為簡潔，且未來可輕易移植到瀏覽器端或其他現代執行環境（如 Bun、Deno）中。

模組協作流程圖

當您執行產生圖表的指令時，內部的呼叫順序如下：

1. 終端機輸入指令 (e.g. draw-cli generate ai-agent)
↓ 解析指令與參數
2. bin/draw-cli.js 呼叫 generate('ai-agent', outputPath)
↓ 尋找註冊的範本
3. src/generator.js 執行對應的模板函式 aiAgentTemplate()
↓ 產生 XML 字串並寫入硬碟
4. 輸出 .drawio 檔案至指定路徑
